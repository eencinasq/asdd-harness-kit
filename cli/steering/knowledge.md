# Knowledge — process memory (mandatory when indexed)

**Source of truth for what the squad already knows.** Index: `.harness/knowledge/`
(regenerated by `asdd sync`; manual: `asdd knowledge sync`).
CLI: `asdd knowledge <query>` — the harness knowledge commands.

Queries:

| Tool | Use |
|------|-----|
| `asdd knowledge search(query, k?, slice_id?)` | Semantic/lexical search over every REQ, spec section, feature, session, and log — **"does this already exist?"** |
| `asdd knowledge trace(id, depth?)` | Graph BFS from any node: REQ→spec→feature→file, DEPENDS_ON chains, sessions |
| `asdd knowledge slice(slice_id)` | JIT bundle: slice node + spec docs + REQs + features + session/log counts — **context pack without opening files** |
| `asdd knowledge status` | Index freshness, counts, active backend (sqlite/jsonl), search mode, and `warnings` when the index is degraded |
| `asdd knowledge patterns(status?)` | Learning loop: repeated failures, overrides, and dismissals grouped as `LP-*` patterns with their `SP-*` proposals and measured effect. Computed live; needs no index ([Learning Gate](./quality-gates.learn.md)) |

Node ids: `slice:<id>`, `req:<slice>:<REQ-…>`, `ac:<slice>:<AC-…>`, `feature:<slice>:<TASK-…>`,
`spec:<slice>:<doc>`, `file:<path>`, `session:<slice>:<file>`, `log:failure_log`, `log:dissent_log`.

## Per-role usage (invariants)

- **KNO-01.** **Discovery / Shape Up / Product Delivery:** `asdd knowledge search`  for overlapping or
  prior capabilities before scoping; `asdd knowledge trace`  on related slices for
  DEPENDS_ON conflicts; `asdd knowledge status`  to confirm the index is fresh.
- **KNO-02.** **Spec / Validation:** `asdd knowledge search`  for duplicate REQs and prior AC wording;
  `asdd knowledge trace`  to verify REQ↔feature traceability claims.
- **KNO-03.** **Task Planning / Implementation:** `asdd knowledge slice`  for the context pack;
  `asdd knowledge trace`  on task nodes for DEPENDS_ON order and OWNS file scopes.
- **KNO-04.** **QA / Refactor:** `asdd knowledge trace`  for coverage (REQ→feature→file);
  `asdd knowledge search`  for similar past failures (`log:*` nodes).
- **KNO-05.** **Knowledge:** `asdd knowledge patterns`  for open patterns before closing a slice (QG-LEARN-04).
- **KNO-06.** **Knowledge Agent:** all four — dedupe detection, blast radius, failure mining.
  It also runs the `codebase-audit` skill, which uses `asdd knowledge trace`  on hotspot
  files; `audit_finding` on the `spec-drift-auditor` server returns the same trace
  for one finding ([spec-drift.md](./spec-drift.md)). Feature nodes carry `evidence_hash`.
- **KNO-07.** If `asdd knowledge status`  reports no index or a stale `generated_at`, run
  `asdd knowledge sync` once before relying on results.

## Negative space

- Not a document store — the index links nodes; specs, sessions, and source stay the SoT (`.harness/specs`, `.harness/state`, repo files).
- No hand-curated facts — the index is generated only; a wrong answer means a missing sync (KNO-07) or a source fix, never an index edit.
- Search results do not satisfy evidence — `asdd knowledge search`  locates; the located artifact still requires `verification` + `evidence_hash` ([session-loop.md](./session-loop.md)).

## Enforcement

`asdd knowledge status`  freshness + `warnings`; `asdd knowledge sync` regenerates the index on every `sync-state`; stale-index reliance is the failure mode KNO-07 covers.

## Escalation

Repeated stale or wrong results → the index build is broken: fix `asdd knowledge sync` via a steering proposal (`QG-LEARN`), do not work around it per-session. A missing index never counts as "no prior art exists".
