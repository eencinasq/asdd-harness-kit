## Decisions

- **One grounding reference, owned by `product-delivery`.** `shape-up` points to it by its installed path
  (`.agents/skills/product-delivery/references/grounding.md`) instead of duplicating it. Not the reverse: skills-spec
  REQ-002 (checked by `cli/test/install.sh`) forbids `product-delivery` from linking into `shape-up/references`.
- **The evidence grammar is not redefined.** Both skills use the ref grammar of
  `external-trackers/references/intent-format.md` (`REQ:<slice>/REQ-NNN`, `slice:<id>`, `path:<repo-path>`, `none`
  only on `New`), so a repo-mode pitch and a PO-mode Intent item are checked by the same rules at intake.
- **PO mode trigger.** `.harness/config/project.json` has a `tracker` block **and** the session is a PO/PM session
  (the `asdd-shaping-agent`, or the user says so). A repository with a tracker block where an engineer runs
  `product-delivery` keeps repo mode unless the user asks for PO mode — engineers import intents with
  `asdd intake` instead.
- **The knowledge index is a local cache.** `asdd knowledge sync` writes `.harness/knowledge/` (gitignored); running
  it is allowed in PO mode, which forbids repository *files*, not caches.
- **Unavailable tool ≠ invented evidence.** If knowledge, codegraph, or metrics cannot run, the row's evidence is
  `PENDING_DEFINITION` and the pitch cannot reach `ready_for_bet` (shape-up) / the scope cannot be `fit`
  (product-delivery).
- **No skill descriptions change** (always-loaded budget in `asdd kit guidance` stays as is).
