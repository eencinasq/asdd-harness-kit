# mutation-testing — Intent

A requirement counts as covered today when an executed test *names* it (DRIFT-04, CONVERGE-02) and, for QA, when "a
specific executed test asserts it". Nothing measures whether that test would notice the code being wrong. Adopt
mutation testing (Uncle Bob's ub-mode "Mutator: cover the uncovered, kill the survivors, delete dead code") as a
deterministic sensor plus the guidance that acts on it.

Mapped files:
- `cli/src/harness/mutate.mjs` (new) and its test — `asdd mutate`, the sensor.
- `cli/registry/contribution-points.json` — the `mutate` command entry (args/flags).
- `cli/templates/bindings/quality-gates.project.md` and `.harness/steering/quality-gates.project.md` — the
  `Mutation command` binding slot.
- `cli/skills/mutation-testing/` (new) and `cli/eval/skills/mutation-testing/` (new) — the skill and its fixtures.
- `cli/agents/asdd-qa-agent.md` — the coverage rule.
- `cli/steering/quality-gates.exec.md` — `QG-SPEC-11` (TL decision 2026-11-23, CON-002).
- `cli/skills/asdd-status`-style index: `.harness/steering/skills.md` (regenerated by `asdd skills-index --write`), `cli/versions.json` (`asdd kit versions`).
- `.semgrep/standards/js.yml` — `std.no-shell-true` exception for the bound-command runner.
- `cli/test/full-pipeline.sh` — the registry smoke run for `mutate`.
- `cli/README.md`, `docs/architecture/domain-model.md` — command row and domain terms.
- `cli/steering/skills.md` — the new index row costs always-loaded bytes; its Negative space bullets (a restatement of
  SKL-02…06) are folded into one line so the steering stays under the REQ-013 cap without raising it.

Not in scope: shipping a mutation tool (the project binds its own: Stryker, mutmut, PIT, cargo-mutants); parsing
tool-specific reports (the contract is the exit code, like `Contract command`); adding a devDependency to the kit.
