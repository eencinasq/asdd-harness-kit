# attack-the-premise — Intent

**Author:** asdd-lite-agent · **Model/Tool:** claude-opus-5-5

Adopt the "Attack the Premise" rule (github.com/unclebob/ub-mode SKILL.md): when two fixes that share one premise
fail the same gate, write that premise in one sentence and decide what to remove before starting another fix.

Today the kit goes from "repeated failure" straight to `blocked` + `docs/agent-failure-log.md` (QG-DEB-05); nothing
asks the agent to diagnose between the second and the third attempt, and no session records a failed attempt per
feature, so no sensor can see the loop.

- `cli/agents/asdd-implementation-agent.md`, `cli/agents/asdd-lite-agent.md`, `cli/steering/session-loop.md` — the
  guide: record each failed attempt as a session with `feature_id` + `failure_signature`; after the second failure
  with one signature, a `checkpoint` session with `premise` (one sentence) and `removes` before a third attempt; a
  third failure → `blocked` as today.
- `cli/src/harness/validators/premise.mjs` (+ `premise.test.mjs`), `cli/src/harness/check-invariants.mjs` — the
  sensor `PREMISE-01` (WARN, in_progress slices only; closed slices are historical evidence, SP-003).
- `cli/src/harness/validators/manifest.mjs` — session schema: `failure_signature`, `premise`, `removes` are
  non-empty strings when present.
- `package.json` — the new test file joins the `npm test` list.
- Installed copies regenerated by `asdd kit self` (`.agents/agents/`, `.cursor/agents/`, `.harness/steering/`,
  `.harness/config/`).

Not in scope: changing the failure-log format, `asdd learn` pattern counting, or the telemetry H-LOOP heuristic.
