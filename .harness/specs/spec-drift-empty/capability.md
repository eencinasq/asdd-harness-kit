# Capability: Empty states and rule generation in spec-drift (spec-drift-empty)

## Category
IMPROVEMENT

## Scope
- Pitch ID: ad-hoc (kit maintenance)
- Scope ID: none — one slice
- Scope class: must_have

## Problem Statement
See [intent.md](./intent.md). The server's three uses (architecture review on the project's Semgrep rules, code review,
and spec audit on the kit's data) must each say clearly when there is nothing to work with, and the architecture review
must offer the way out (rules generated by the agent from the codebase) instead of an error or a false pass.

## Actors
- Tech Lead: runs the tools from a chat host and reads the dashboards.
- Host agent: the model in the chat host; writes rule files when the user asks.

## Entities
- Rule set: Semgrep YAML under `.semgrep/architecture/` and `.semgrep/standards/`.
- Rules-generation prompt: instructions for the host agent to write a rule set from this codebase.
- No-data result: a tool result that states there is nothing to show, why, and the next step.

## Out of Scope
PR review changes; generating rules on the server; installing the kit from the server.
