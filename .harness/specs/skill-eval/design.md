## Fixture format

One JSON file per case under `cli/eval/skills/<skill>/<case>.json`; the skill under test is the directory name.

```json
{
  "id": "status-json",
  "task": "Report pipeline health as JSON",
  "expect": "asdd status --json exits 0 and lists slices",
  "setup": { "path/in/workspace": "file content" },
  "probes": [{ "id": "p1", "run": "node cli/bin/asdd.mjs status --json", "cwd": "repo" }],
  "assertions": [
    { "type": "exit_code", "probe": "p1", "code": 0 },
    { "type": "stdout_contains", "probe": "p1", "text": "\"slices\"" },
    { "type": "skill_contains", "pattern": "asdd status" }
  ]
}
```

- `task` / `expect` are the REQ-002 input task and expected observable outcome (documentation fields; `expect` is also echoed in failure output).
- `setup` (optional) seeds a `mkdtemp` workspace; probes default `cwd: "work"` (that workspace) or `"repo"` (the kit repo root, for read-only commands). Probes run via `spawnSync` with `shell: true`, a timeout, and captured stdout/stderr/status — deterministic, no model.
- Assertion types: `exit_code`, `stdout_contains`, `stdout_matches` (regex), `file_exists`, `file_contains` (path relative to the work dir), `skill_contains`, `skill_lacks` (evaluated against the resolved SKILL.md — the worktree file, or `git show <ref>:<path>` under `--baseline`). This is what makes the baseline meaningful: the same fixture is re-scored against the old skill body.

## Skill body resolution

Skill name = fixture directory. Candidate paths, first hit wins: `cli/skills/<name>/SKILL.md`, then `.agents/skills/<name>/SKILL.md`. Missing skill → fixture error (counts as failed, named in the report). `--baseline <ref>` resolves the same repo-relative path via `git show <ref>:<path>`; a git failure marks every fixture of that skill as errored, never checks out the tree.

## Baseline delta and exit status

Per fixture, compare current vs baseline pass/fail: `improved` (baseline fail → current pass), `regressed` (baseline pass → current fail/error), `unchanged` (same outcome, including new fixtures absent at baseline reported as `new`). Without `--baseline`: exit 1 when any fixture fails. With `--baseline`: exit 1 only when any fixture `regressed` — REQ-004 — and the report names them. `--json` emits the full suite object; human output is a per-skill pass-rate table plus delta lines.

## Risks

- Fixture commands that need a live model/runtime would force lite escalation (E1/E4). Mitigation: starter fixtures probe only deterministic CLI surfaces (`asdd status --json`, `codegraph --version`/`status`) and skill-body assertions; if a needed probe can't run deterministically, STOP and report instead of adding an adapter.
- `git show` path resolution differs between kit repo (`cli/skills/`) and installed projects (`.agents/skills/`); mitigated by the candidate-path order above and an explicit error when neither exists.
- Probe `cwd: "repo"` runs read-only commands only; fixtures must not mutate the repo (asserted by convention + review, same as converge-eval's temp-dir approach for writes).
