## Goal

> **A rule in `asdd-harness-kit` is a declarative, mechanically falsifiable invariant with mandatory negative space and an escalation gate — never a runbook, never a persona, never an unverifiable preference. Two profiles govern where rules live (`AGENTS.md` at directory root; `.agents/rules/<name>.md` for single-concern policies); one precedence law governs how rules compose with agents, skills, prompts, and steering.**

Bloom-calibrated objective (`blooms.taxonomy.md`): **Analyze** (C4×Conceptual) the kit rule inventory against `rule.spec.md` → **Evaluate** (C5) which spec elements are normative for the kit's canonical formats and which fleet defects are real → **Create** (C6) the ratified profiles + convergence contract + phase plan. One dominant level per phase; proof is level-appropriate (citations for C4, applied criteria for C5, a constraint checklist for C6).

1. **Two profiles, zero hybrids** — `directory_root` and `modular_policy` instantiate `rule.spec` §2 grammar; the kit adds exactly one declared adaptation surface (`contract-doc` `_`-files) and delegates its third rule-bearing surface (`.harness/steering/`) to the sibling's `kit_steering_rule`.
2. **Rules outrank everything they govern** — agents, skills, prompts, and steering operate inside rule negative space; a rule never silently contradicts a higher-level rule without an override declaration (`R-011`).
3. **Fleet audited, not rewritten** — the conformance matrix is the migration backlog; Phase 1 changes zero kit files. Guardrails and wiring are spec'd for landing; existing rule-bearing artifacts conform-on-touch.

### 3.2 Steering integration — the demarcation law

`rule.spec` defines a `rule` as "a persistent, declarative invariant, policy, or boundary set" (§1) — `.harness/steering/*.md` satisfies that definition, so steering **is** rule-class content. What differs is the *discovery contract*:

- **`.agents/rules/*.md` → `modular_policy`:** contextual loading. Referenced by `AGENTS.md`/charters (`rule.spec` §1: "referenced by charters and root rules") or discovered by path conventions; no frontmatter keys required; scope declared in prose (`Apply this rule whenever…`).
- **`.harness/steering/*.md` → `kit_steering_rule` (sibling profile):** JIT loading. Mandatory `inclusion`/`tags` frontmatter parsed by `steering-tags.mjs`; injected only when the slice phase/mode/role intersects (`_runtime-template.md:13`); governed by the sibling's slot grammar + registry.

**Demarcation test (mechanical):** *If the content must hold unconditionally for every actor in its path scope → `modular_policy` (or `directory_root`). If it must hold only when a phase/mode/role matches → `kit_steering_rule`.* A file carrying `inclusion:`/`tags:` under `.agents/rules/` fails lint; a `.harness/steering/` file lacking them currently emits `warn` (`steering-tags.mjs:35-37`) — the sibling's `D-11` upgrades missing frontmatter to `fail`. Precedence between the surfaces is disjoint by scope — on a genuine overlap the higher-level source is `AGENTS.md` non-negotiables + `controls.md` precedence, and the conflict itself is a finding (`DOM-002`), never silently resolved.

### 3.3 Precedence & composition law

```text
Workspace rules (AGENTS.md + .agents/rules/*.md, hierarchical: leaf > parent > global)
        │  governs / out-ranks
        ▼
Domain charters (_prompt.md) ──► Orchestrator agent ──► Subagent ──► Mounted skill
        (grounds truth)            (dispatch contract)     (bounded)     (procedure)
        │
        └── steering (.harness/steering/*.md) — rule-class, tag-scoped,
            same negative-space authority inside its JIT window
```

1. **Rule > Agent:** every agent inherits active `AGENTS.md` + `.agents/rules/*.md` (`agent.spec` §1.2.1, `A-023`); cross-cutting policies live in root rules, never duplicated into agent files.
2. **Agent → Skill:** agents delegate procedural mechanics to skills (`agent.spec` §1.2.2) — the mechanism by which `R-003` extractions land: a rule's procedure moves to a skill; the rule keeps the boundary.
3. **Prompt ⊂ Rule:** `_prompt.md` charters may tighten a domain's negative space but never relax a workspace rule (`prompt.spec` §4 constraints slot).
4. **Steering ≅ Rule:** tag-scoped rule subtype; where steering and modular rules genuinely conflict, `controls.md` precedence + this proposal's `D-3` law arbitrates — declared, never inferred.

### D-8 · Runtime projection strategy — reference discovery now, generated adapters later

- **Context:** `Q-R5`. No runtime natively loads `.agents/rules/` (`G-14`); the vault's working model resolves modular rules through the root `AGENTS.md` §4 routing table — `AGENTS.md` is always-on in every runtime (`install-into.sh:831` seeds it; `opencode.json` `instructions:["AGENTS.md"]` `:1335`; `CLAUDE.md` points at it `:1242`). **Bound-vs-visible gap (`AR-7`):** the reference chain reaches the orchestrator, but a mounted subagent's context is its agent file + `_runtime-template` — which never enumerates `.agents/rules/` — so a modular rule can be invisible to the executing actor.
- **Decision:** Phase 1 codifies **reference discovery** as canonical: `AGENTS.md` carries a rules section/routing table naming each `.agents/rules/` file and its trigger (the vault model, empirically proven). Phase 2 adds: (a) *mounted-propagation* — `_runtime-template.md` (or generated per-agent references) enumerates the active modular rules so bound subagents actually see them (`AR-7` guardrail); (b) *generated* projections — marker-delimited `.cursor/rules/*.mdc` adapters and a generated rules-table block in `AGENTS.md` — parity with the sibling's `D-12` registry-generated projections, driven from the same source to kill the `G-8`/`G-9` drift class.
- **Consequences:** zero new runtime wiring in Phase 1 — rules work in every runtime the kit already supports for orchestrators; projection drift becomes a checkable diff (generated vs source) instead of silent hand-maintenance; the subagent visibility hole is closed by design before rules proliferate.
- **EARS:** WHEN a `.agents/rules/` file exists, `AGENTS.md` SHALL reference it with an explicit trigger line, and no runtime adapter SHALL duplicate a hand-maintained copy of its body; WHEN a mounted subagent context is built, the mount contract or dispatch contract SHALL enumerate the active `.agents/rules/` files it is bound by, and a rule SHALL NOT be considered binding on that actor if no reference reaches it; WHEN generated projections exist, a marker-delimited block SHALL delimit them and a drift check SHALL fail on divergence.

## 8. Invariants

1. **`R-NNN` citations verbatim:** every spec rule cited by its `R-001`–`R-012` / `§n.n` ID; no invented spec rules or tags.
2. **Four-artifact separation:** rules define boundaries; skills define procedures; agents define actors; prompts define instructions — steering is a declared `rule` subtype, nothing else.
3. **`AGENTS.md` frontmatter prohibition:** `directory_root` files never carry YAML frontmatter (`R-005`); `modular_policy` files never carry `inclusion:`/`tags:` (`D-2`).
4. **Mechanical falsifiability:** every invariant in a conforming rule is checkable by a command, a checklist, or a declared `reviewer-enforced` lens — zero platitudes.
5. **Mandatory negative space + escalation:** every conforming rule declares prohibitions and a structured halt gate — no positive-only policy ships.
6. **Disjoint surfaces:** `.agents/rules/` (unconditional) vs `.harness/steering/` (JIT tag-scoped) — one file, one grammar; conflicts are findings, never silent merges.
7. **Phase 1 modifies zero kit files:** landing/retrofit executes only post-ratification; existing rule-bearing artifacts conform-on-touch.
8. **Declared siblings only:** `skills/v7`, `agents/v2`, `harness.stearing/v1` inform via cited decisions — no silent inheritance; lineage files immutable once reviewed.
9. **Budget honesty:** 24 KB/file hard cap; aggregate measured in tiers, raised only by recorded decisions.
10. **No invisible binding:** a rule binds an actor only when a reference reaches that actor's context — orchestrators via `AGENTS.md`, mounted subagents via mount/dispatch contract (`D-8`, `AR-7`).
