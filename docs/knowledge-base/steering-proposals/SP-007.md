- `feat/telemetry-emitters` was forked from `chore/p5-roadmap-runtimes-bindings` at `1b1fbae` and merged that branch twice (`0642476`, `f41a3ff`). `git merge-base --is-ancestor 1b1fbae main` exits 1: `main` does not contain the base yet.

- The Stop hook is `node cli/bin/asdd.mjs verify` (`.claude/settings.json`, `Stop`), with no drift base in its environment, so it resolves to `main`. The only other reader of the env var is `cli/src/harness/ui-server.mjs:134`.
- Reported by the implementation session: on `main` as the base, DRIFT-01 FAILs 13 inherited files (`cli/eval/skills/*`, `cli/src/kit/{fingerprint,guidance}.mjs`, three `cli/steering/*` files, SP-003…SP-006) as "not mapped by telemetry-emitters". With `HARNESS_DRIFT_BASE=chore/p5-roadmap-runtimes-bindings`, `asdd check --live` exits 0.

## Root cause

DRIFT-01 assumes that every branch forks from the integration branch, either `main` or one repo-wide binding. P5 runs three parallel worktrees (skill-eval, asdd-ui, telemetry-emitters), all stacked on the same non-main base. For a stacked branch, `main...HEAD` contains the whole base branch, so DRIFT-01 charges base commits to whichever slice is in an edit phase. That is a misattribution, not gold-plating. The slice cannot fix it by mapping the files, because it does not own them.

SP-004 (rejected, 2026-11-16) chose an operational control: "parallel agents set `HARNESS_DRIFT_BASE`". That control cannot reach the sensor that matters. The Stop hook is spawned by the runtime, not by the agent's shell, so an `export` in an agent's Bash call never reaches it. The variable has no recorded home, and the only durable binding is a committed, repo-wide file. Every Stop therefore FAILed. The local signals opened this pattern, and through QG-LEARN-04 they also opened LP-7f51c52f (see SP-008). The sensor's rule is correct. Its base resolution has no per-branch input that hooks can see.

## Change

Options considered:

| # | Option | Pros | Cons |
|---|--------|------|------|
| A | Keep env only (status quo from SP-004) and document an `export` in each worktree's shell profile or hook command | No code change | Hooks do not inherit it reliably. Editing `.claude/settings.json` per worktree is a committed file that merges back. Every runtime (Cursor, Devin, Codex) needs its own wiring. This is the control that already failed. |
| B | Set the `Drift base branch` binding in `quality-gates.project.md` per branch | Uses the existing binding | The file is committed and shared. A stacked value leaks into `main` at merge, and the three worktrees would conflict on it. |
| C | Auto-detect the fork point (`git merge-base --fork-point`, or `@{upstream}`) | Zero configuration | `--fork-point` depends on the reflog: it is unreliable in fresh worktrees and after rebase. `@{upstream}` is usually `origin/<same branch>` after `git push -u`, which makes the diff empty and silently blinds the sensor. |
| **D** | **A recorded per-branch git config key, `branch.<name>.asddDriftBase`, read by `resolveBase` after the env var and before the repo-wide binding. When both resolve, pick the nearest merge-base.** | Per-branch and per-worktree (git `branch.*` keys are branch-scoped). Not committed, so nothing leaks into `main`. Hooks of every runtime see it with no env plumbing, because `resolveBase` already shells out to git. Explicit and auditable (`git config --get-regexp asddDriftBase`). | Local to the clone: each clone or CI job must record it (CI already diffs PRs against their target). Needs one setter so agents do not hand-type it. |

**Recommendation: D.**

1. In `resolveBase`, add the candidate `git config --get branch.<current>.asddDriftBase` right after `process.env.HARNESS_DRIFT_BASE`.
2. Nearest base: when the recorded base and the binding/default base both resolve, use the merge-base that descends from the other (`git merge-base --is-ancestor`). Once the stacked base lands on `main` and `main` is merged back, the stale key then falls through to `main` on its own and does not miss newer drift.
3. Never accept a base whose merge-base equals `HEAD` while the branch has commits ahead of the default base. Fall through, so the sensor cannot be blinded.
4. Print the resolved base (`ref@sha`) in the DRIFT-01 FAIL line, so a misattribution can be seen in the signal.
5. Setter: `asdd drift --set-base <ref>` (or the worktree/init flow) writes the key. `cli/steering/spec-drift.md` documents the resolution order and the stacked-worktree case next to the existing `Drift base branch` paragraph.

This does not loosen DRIFT-01: no path is exempted, and every change made on the branch itself is still checked. It does not contradict SP-004, which rejected loosening for `docs/**`. It replaces SP-004's unreachable env-var process with a recorded binding that the sensor reads.
