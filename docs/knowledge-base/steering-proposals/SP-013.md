## Pattern

- **Pattern:** LP-130d8d22 (`blocked:phase:validation`, escape)
- **Occurrences:** 3
- **Slices:** jev-module, kit-hygiene, mutation-testing

Evidence:

- Validation Gate BLOCK (QG-VAL-01): VAL-001 on MUST REQ-005 - upgrade detection enables Jev on every existing project with no way off. Validation confidence 0.78.
- Validation Gate BLOCK (QG-VAL-01): VAL-001 BLOCKING on MUST REQ-008 - upgrade behavior for existing hook configs undefined; installer substring match would keep the old path forever. Validation confidence 0.80. Report: .harness/specs/kit-hygiene/spec-validation-report.md
- spec-validation-report.md: BLOCK (CON-001 BLOCKING; CON-002..004, AMB-001/002 HIGH; 8 MEDIUM, 2 LOW). Back to spec.

## Root cause

Escape. All three Validation BLOCKs are the same defect: a MUST requirement that contradicts behavior or a contract the system already has — jev-module REQ-005 vs existing installs on upgrade, kit-hygiene REQ-008 vs existing hook configs and the installer's substring match, mutation-testing REQ-007/008 ("record the equivalent mutant") vs the exit-code contract the same spec chose. The Validation agent caught each one (the sensor works); the Spec agent's guide never asks it to name the existing behavior a requirement meets, so each one reached validation.

## Change

One rule in the Spec agent's protocol: for each MUST requirement that changes or reads existing behavior (an upgrade of an installed project, an existing config or hook, a sensor's output or exit contract), cite that behavior with `file:line` and state in one sentence how the requirement agrees with it; an unresolved disagreement is a `PENDING_DEFINITION`, not a requirement.

## Success criterion

asdd learn tracks `blocked:phase:validation`; the pattern goes quiet when the next full slices pass validation without a contradiction-with-existing-behavior BLOCK. A BLOCK for another reason is not a recurrence of this root cause.

## Rollback

Revert the one rule in `cli/agents/asdd-spec-agent.md` and its eval case.
