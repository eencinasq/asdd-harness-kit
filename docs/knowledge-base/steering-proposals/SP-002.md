## Pattern

- **Pattern:** LP-0e072262 (`failure:planning:shared-files-across-serial-tasks`, escape)
- **Occurrences:** 6
- **Slices:** kit-hygiene

Evidence:

- TASK-003 edited files owned by TASK-001 (scripts/test-install-into.sh); DRIFT-02 reopened the earlier feature(s) and forced re-verification.
- TASK-004 edited files owned by TASK-003 (asdd-implementation-agent.md, asdd-discovery-agent.md); DRIFT-02 reopened the earlier feature(s) and forced re-verification.
- TASK-005 edited files owned by TASK-001, TASK-003, TASK-004 (test-install-into.sh, package.json, install-into.sh, implementation agent); DRIFT-02 reopened the earlier feature(s) and forced re-verification.

## Root cause

The task-planning guide (line 155) only says tasks with overlapping scopes "must be serialized or replanned". Serializing satisfies it, so kit-hygiene planned seven serial tasks that shared `scripts/test-install-into.sh`, `scripts/install-into.sh`, `package.json`, and agent prompts. DRIFT-02 then worked as designed: every later task that touched a shared file made an earlier feature's evidence stale, and each of six occurrences cost a re-verification and an extra commit. The sensor is right (the earlier evidence really was stale); the guide let the plan create the churn.

## Change

In `.agents/agents/asdd-task-planning-agent.md`, replace "Tasks with overlapping scopes must be serialized or replanned." with:

> Give each file one owning task. When several tasks must edit the same file (a shared test harness, the installer, `package.json`), either move those edits into one task, or put that file only in the last task that touches it and list it under that task's `Files affected`; earlier tasks then verify without editing it. Overlapping scopes between concurrent tasks remain forbidden.
