# SP-005 — DRIFT-02 should not reopen verified features of closed slices

## Pattern

- **Pattern:** LP-f374bf6d (`sensor:DRIFT-02`, escape)
- **Occurrences:** 4 (×5 after the skill-eval shared-file edits)
- **Slices:** cli-harness, skills-spec, agents-spec, asdd-p0…p4, kit-playbook (all DONE)

Evidence:

- feat/skill-eval edited shared registration files (`cli/src/harness/commands.mjs`, `package.json`, `README.md`) — all mandated append-only edits — which reopened 16 `passing` features across 8 DONE slices whose `scope_paths` include those files.
- DRIFT-02 passing feature TASK-005 changed after evidence_commit 9a45bdd; set it back to in_progress and rerun verification
- DRIFT-02 passing feature TASK-001 changed after its verification (scope_paths no longer match evidence_hash); set it back to in_progress and rerun verification
- DRIFT-02 passing feature TASK-001 changed after evidence_commit 67f5a59; set it back to in_progress and rerun verification

## Root cause

`runDrift` in `drift-lib.mjs` computes DRIFT-02 for every `passing` feature in every slice's features file, regardless of the owning slice's lifecycle status. Shared append-only registration files (`commands.mjs`, `package.json`, `README.md`, `docs/ASDD-ROADMAP.md`) are inside many old features' `scope_paths`, so any later slice that legitimately edits them — exactly what the P5 parallel-work rules require — invalidates evidence hashes of slices that closed long ago. The remediation (flip to `in_progress`, rerun verification, restamp) is then repeated as chore work on slices nobody is actively working, producing recurring FAIL noise that trains agents to ignore the sensor. This is sensor noise, not an escape: the old features' behavior was not actually broken (all 16 verifications re-ran green).

## Change

In `cli/src/harness/drift-lib.mjs`, when collecting `passing` features for DRIFT-02 (and DRIFT-05), skip features whose owning slice status is `DONE`, `ABANDONED`, or `PARKED`. Open slices (`in_progress`, `blocked`, etc.) keep full DRIFT-02 coverage. The slice status is already available from the same manifests `runDrift` reads.

## Success criterion

`asdd check` on a branch that only appends to shared registration files produces zero DRIFT-02 FAILs for features of DONE slices, while a feature of an open slice whose scoped file changes still FAILs. `asdd learn` stops recording `sensor:DRIFT-02` occurrences attributable to closed slices.

## Rollback

Revert the status filter in `drift-lib.mjs`; DRIFT-02 returns to covering all slices.
