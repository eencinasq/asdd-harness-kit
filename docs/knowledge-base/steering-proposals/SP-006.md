# SP-006 — DRIFT-01 exempts the append-only harness logs under docs/

## Pattern

- **Pattern:** LP-06528643 (`sensor:DRIFT-01:docs`, escape)
- **Occurrences:** 3
- **Slices:** jev-module, skill-eval

Evidence:

- DRIFT-01 docs/agent-failure-log.md changed but is not mapped by jev-module (intent/design/tasks/spec or scope_paths)
- DRIFT-01 docs/ASDD-ROADMAP.md changed but is not mapped by agents-use-scripts, asdd-cli, cli-harness, jev-gate-nest, knowledge-nest, mcp-standalone, modules-top-level, spec-drift-merge, spec-drift-adoption (intent/design/tasks/spec or scope_paths)
- DRIFT-01 docs/ASDD-ROADMAP.md changed but is not mapped by skill-eval (intent/design/tasks/spec or scope_paths)

## Root cause

Two different defects share the `docs/` signature. (1) `docs/agent-failure-log.md` and `docs/dissent-log.md` are append-only harness records every slice may write at session close — the same class as session files and the features tracker, which DRIFT-01 already treats as harness records — but they are not in the mapped set, so a mandatory write is reported as an escape. (2) `docs/ASDD-ROADMAP.md` is a shared product document: commits on a long-lived base branch (and parallel P5 worktrees forked from it) change it outside any single slice's mapping, and `changedFiles` diffs against `main`, attributing those changes to whichever slice is in implementation. The second cause is only partly a sensor defect — a slice that legitimately edits the roadmap should map it — but base-branch commits can never be mapped by the running slice.

## Change

In `cli/src/harness/drift-lib.mjs`, treat `docs/agent-failure-log.md` and `docs/dissent-log.md` as always-mapped harness records (same exemption class as `.harness/state/**` session files), so DRIFT-01 stops failing on mandatory session-close writes. Leave `docs/ASDD-ROADMAP.md` and other product docs subject to mapping; whether base-branch attribution needs a separate sensor change (e.g. per-slice base ref) is left to the Tech Lead's decision below.

## Success criterion

No `sensor:DRIFT-01:docs` recurrence for the two log paths over the next 10 sessions; `asdd learn` tracks recurrence of the signature automatically. Roadmap-attribution recurrences should be handled by mapping the file in the editing slice's spec, not by widening the exemption.

## Rollback

Revert the exemption list in `drift-lib.mjs`; DRIFT-01 returns to flagging the log paths.

## Decision

**accepted** — 2026-11-16, Tech Lead eencinas.

Reason: `docs/agent-failure-log.md` and `docs/dissent-log.md` are append-only harness records any slice must write; charging them to DRIFT-01 is noise. Narrower than SP-004, which stays rejected: every other file under `docs/` must still be mapped. Base-branch attribution needs no separate proposal: parallel worktrees set `HARNESS_DRIFT_BASE` to their fork commit (SP-004). Pending implementation (`applied` once the control change lands).

> Renumbered from SP-004 at integration (2026-11-16): SP-004 already records the Tech Lead's rejection of loosening DRIFT-01 for `docs/` (same pattern, drafted in slice asdd-ui). This narrower proposal (exempt only the append-only logs) stays `proposed` for a separate decision.
