## Pattern

- **Pattern:** LP-06528643 (`sensor:DRIFT-01:docs`, escape)
- **Occurrences:** 3
- **Slices:** asdd-ui, jev-module

Evidence:

- DRIFT-01 docs/agent-failure-log.md changed but is not mapped by jev-module (intent/design/tasks/spec or scope_paths)
- DRIFT-01 docs/ASDD-ROADMAP.md changed but is not mapped by agents-use-scripts, asdd-cli, cli-harness, jev-gate-nest, knowledge-nest, mcp-standalone, modules-top-level, spec-drift-merge, spec-drift-adoption (intent/design/tasks/spec or scope_paths)
- DRIFT-01 docs/ASDD-ROADMAP.md changed but is not mapped by asdd-ui (intent/design/tasks/spec or scope_paths)

## Root cause

DRIFT-01 correctly requires every product-file change on the branch to be mapped by an editing slice. The recurring `docs/*` hits are mostly **base-branch noise**: a prior commit (e.g. P5 roadmap on `docs/ASDD-ROADMAP.md`, already mapped by DONE slice `asdd-roadmap`) sits between `main` and a worktree forked mid-lineage. When a later slice (asdd-ui, jev-module, …) enters an edit phase, `check --live` diffs against `main` and attributes those historical docs edits to the active slice. That is not gold-plating by the active agent; loosening DRIFT-01 for `docs/**` would also hide real unmapped doc edits.

## Change

**Rejected alternative:** loosen DRIFT-01 (or the drift base binding in `.harness/steering/quality-gates.project.md`) so `docs/**` changes inherited from the fork base do not fail an unrelated editing slice.

**Preferred operational control (no sensor change):** parallel agents set `HARNESS_DRIFT_BASE` to the shared fork commit (here `1b1fbae` / `chore/p5-roadmap-runtimes-bindings`). Intentional doc edits still require a Mapped line on the owning slice.

## Success criterion

Not applicable for a `rejected` decision. Recurrence of `sensor:DRIFT-01:docs` under a wrong drift base is expected until agents set `HARNESS_DRIFT_BASE`; that is process, not a sensor defect.

## Rollback

None — no control file change.

## Decision

**rejected** (won't fix / won't loosen) — 2026-11-16, Tech Lead eencinas. Drafted by the Cursor agent (slice asdd-ui); decision confirmed by the Tech Lead during integration.

Reason: keep DRIFT-01 strict for docs. Close LP-06528643 without a sensor or binding change. Parallel P5 worktrees use `HARNESS_DRIFT_BASE=<fork>` so inherited roadmap/doc commits are not charged to wave-1 slices.
