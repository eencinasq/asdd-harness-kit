## Root cause

The signature comes from the blocked-session collector (`cli/src/harness/learning-lib.mjs:444`). It turns every `phase_blocked` session into `blocked:phase:<phase>` and classifies it as an escape. A QA `phase_blocked` is the Spec Coverage Gate (QG-SPEC-05/06) stopping a slice that has an untested MUST requirement. In all three occurrences the gate did that.

- **telemetry-emitters:** the block caught a real defect, UNCOV-001. `telemetry-observe.mjs:14` statically imports the library, so `asdd observe` exits 1 when that library throws or is deleted. The block sent the slice back to implementation (TASK-010 reopened).
- **jev-module and kit-hygiene:** their QA blocks were resolved, and they completed Knowledge (`2026-10-28T22:30:47Z` and `2026-10-28T01:41:41Z`, from their `phase_completed-knowledge` sessions) before this pattern existed.

Three slices hit the same gate with unrelated causes. That shows the sensor is working. No single guide failed to steer the agents, so there is no guide gap to close.

## Change

None. The option considered was to drop QA `phase_blocked` sessions from signal capture, or to classify them as non-escapes (`loosen-sensor` on the learning sensor). It was not taken. A QA block that recurs for the same reason within one slice is still worth surfacing, and blocks counted across slices are a useful process metric.
