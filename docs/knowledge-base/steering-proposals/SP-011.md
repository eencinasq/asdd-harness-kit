# SP-004 — Re-verify scope_paths hash when modifying shared platform files

## Pattern

- **Pattern:** LP-f374bf6d (`sensor:DRIFT-02`, escape)
- **Occurrences:** 4
- **Slices:** —

Evidence:

- DRIFT-02 passing feature TASK-005 changed after evidence_commit 9a45bdd; set it back to in_progress and rerun verification
- DRIFT-02 passing feature TASK-001 changed after its verification (scope_paths no longer match evidence_hash); set it back to in_progress and rerun verification
- DRIFT-02 passing feature TASK-001 changed after evidence_commit 67f5a59; set it back to in_progress and rerun verification

## Root cause

When shared infrastructure or documentation files are modified in a later slice, earlier slices that mapped those files fail DRIFT-02 because the recorded evidence_hash was computed against the previous file content. The session-loop guide needs explicit guidance on refreshing evidence_hash after architectural refactoring.

## Change

In `.harness/steering/session-loop.md`, document that cross-cutting edits to files mapped by prior slices require updating evidence hashes via `asdd converge` and `asdd sync`.
