## Pattern

- **Pattern:** LP-b028f255 (`warn:QG-DEC-09`, noise)
- **Occurrences:** 5
- **Slices:** agents-use-scripts, sensor-fixes

Evidence:

- QG-DEC-09 slice "sensor-fixes": validation completed (sess-sensor-fixes-009) with no spec gate recorded
- QG-DEC-09 slice "agents-use-scripts": qa completed (sess-agents-use-scripts-009) with no implementation gate recorded

## Root cause

Noise. `validators/phase-chain.mjs` re-reads every slice's sessions on every `asdd check`, closed ones included. Of the 12 slices that emit QG-DEC-09 today, 11 are DONE or ABANDONED (agents-use-scripts, asdd-cli, cli-harness, jev-gate-nest, knowledge-nest, mcp-standalone, modules-top-level, spec-drift-merge, sensor-fixes, telemetry-emitters, cli-args); only platform-spec is in_progress. A closed slice's session log is append-only history, so the same WARNs repeat on every run and catch nothing new — and since QG-LEARN-08 records WARN lines, Verify-on-Stop runs turn that repetition into an open pattern that then fails QG-LEARN-04 on the closed slices that contributed. DRIFT-02 already treats closed slices as historical evidence (SP-003); the phase chain does not.

## Change

In `validators/phase-chain.mjs`, report phase-chain findings only for slices whose status is `in_progress` (same rule as DRIFT-02, SP-003). Amending a DONE slice (`asdd slice amend`) makes it in_progress again, so a re-opened slice is still checked. No change to the gates themselves or to `deriveGates`.

## Success criterion

`asdd check` prints no QG-DEC-09 for closed slices; `asdd learn` stops recording warn:QG-DEC-09 from them, so LP-b028f255 goes quiet and then verified. The full-pipeline e2e keeps proving that an in_progress slice that completes design without a validation gate is still flagged.

## Rollback

Revert the status filter in `validators/phase-chain.mjs` (one condition).
